# Evidence

**Every rule and guard here was paid for**, by skills that ran unattended on a real project and did
exactly what their words said.

## E-01 · The entry that taught instead of routing

A skill's entry grew to hundreds of lines, all of them loaded on every call. The one rule a run
broke again and again sat far down the page, below the steps, a diagram and a table.

## E-02 · Pointers are load-bearing

The first pointer check written for a family of skills still found paths to files that had moved,
and heading pointers that resolved only by guessing which skill a bare file name meant.

## E-03 · Numbers written before they existed

A run wrote the measured time of several steps before the commits that ended them, cited a
stylesheet one line off from an offset it had counted itself, and stamped a booking ahead of the
clock. Every structural rule held on every file throughout.

## E-04 · Zeros that were set aside

A dashboard drew three measurements as zero. They had been set aside, because their evidence
predated the code, and the only sign of it was one line reading `… withheld`. A person read the
zeros as losses. The script that drew them had been tested only on fresh inputs.

## E-05 · A job refused by one input

A long capture job was refused whole at its start, because one item on its list named something the
tool cannot produce. The list had been written from a report and never checked against what the tool
accepts.

## E-06 · A label that lost its name

A tab bar's label was drawn with a function so that one tab could be bold. The navigator builds each
tab's spoken name only from a label that is a string, so every tab lost it, and with it the names
the end-to-end tests selected tabs by. The component test drew the label alone and passed. A review
that read the navigator's own source found it.

## E-07 · Two edits where one was meant

An edit script replaced a block by its text, and the same block closed two tests. Both changed, a
helper was declared twice, and the file failed to load. Failing at once is the lucky case; a second
match that still parses is not seen at all.

## E-08 · A page for people, with nowhere to put it

A set of skills was to be published, and none had a page a person could read before installing one.
The only file every skill has is its entry, which the host loads on every call and the model follows
as instructions, so a pitch written there would be obeyed. A README beside the entry is the page for
people, and nothing the model reads depends on it.

## E-09 · Rules that held only a layout

An earlier version of this builder held twelve rules. Eight of them enforced a folder layout, cost
dozens of commits and several rewrites to keep, and are recorded catching nothing. The four kept are
the ones a failure above stands behind.
